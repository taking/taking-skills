# 도메인 용어 표와 한국어-영어 용어 관례

한 개념에는 한 용어만 씁니다. 같은 것을 `전송로`, `스트림`, `채널`로 번갈아 부르면 독자가 같은 것인지 확인해야 합니다. 이 규칙을 지키려면 프로젝트마다 **도메인 용어 표**가 하나 있어야 합니다. 이 문서는 그 표를 만들고 유지하는 법과, 어떤 말을 한국어로 옮기고 어떤 말을 영어로 둘지 정하는 관례를 담습니다.

## 1. 도메인 용어 표

용어 표는 프로젝트의 개요 문서나 README 한 곳에 둡니다. 다른 문서는 이 표를 가리키고 정의를 중복하지 않습니다.

| 열 | 내용 |
| --- | --- |
| 용어 | 문서 전체에서 쓸 하나의 표기 |
| 정의 | 한 줄 정의. 범위가 흐린 말을 쓰지 않습니다 |
| 영어 원어 | 대응하는 영어 용어나 코드 식별자 |
| 쓰지 않을 말 | 같은 개념을 가리키던 다른 표기(통일 대상) |

예:

| 용어 | 정의 | 영어 원어 | 쓰지 않을 말 |
| --- | --- | --- | --- |
| 터널 | 에이전트가 먼저 연 역방향 gRPC 스트림 | tunnel | 전송로, 채널 |
| 이벤트 스트림 | Kafka로 이벤트를 보내는 경로 | events stream | 이벤트 채널 |

## 2. 유지 규칙

- 용어를 새로 정하면 표에 먼저 올리고 문서에서 그 표기만 씁니다.
- 코드 식별자, API 이름, 설정 키는 원문 그대로 둡니다. 임의로 번역하지 않습니다.
- 표기를 바꾸면 표의 `쓰지 않을 말`에 이전 표기를 남겨 과거 문서와 이어지게 합니다.
- 요구 문장의 용어도 이 표를 따릅니다([requirement-levels.md](requirement-levels.md) §2 참고).

## 3. 한국어-영어 용어 관례

산문은 한국어로 쓰고, 정착된 기술 용어는 영어로 둡니다. 번역하면 의미가 달라지는 용어는 원어를 유지합니다.

| 처리 | 대상 | 예 |
| --- | --- | --- |
| 영어 그대로 | 널리 통용되는 인프라, 언어 용어 | Pod, Namespace, Deployment, Context, Goroutine, Mutex, Kafka Topic, Consumer Group, Offset |
| 영어 그대로 | 코드 식별자, API, 설정 키, 파일명 | `InteractiveSessionLimiter`, `--advertise-routes`, `ts-corp-01` |
| 한국어로 | 명확한 정착 한국어가 있는 일반어 | 요청, 응답, 재시도, 캐시 적중, 권한 |
| 첫 등장만 포인터 | 의미를 가리는 개념어 | 멱등(idempotent), 수렴(reconcile), 순단 |

판단 기준:

- 널리 쓰는 영어 용어를 억지로 번역하지 않습니다. 명확한 한국어 정착어가 있을 때만 번역합니다.
- `단어(Word)` 식 이중표기를 남발하지 않습니다. 기본은 "산문은 한국어, 용어는 영어"입니다.
- 코드 주석의 계약 용어는 영어 관례를 따릅니다([../code-comments/style-guide.md](../code-comments/style-guide.md) §14).
