# 커밋 메시지, PR 본문 규칙

커밋과 PR도 기술 문서입니다. 문서, 주석과 같은 원칙(번역투, AI 문체 제거, What→Why, 표, 불릿 우선)을 적용합니다.

## Overview

| 대상 | 핵심 |
| --- | --- |
| 커밋 제목 | `<type>[scope]: 요약`, 명령형, 72자 이내, 끝 마침표 없음 |
| 커밋 본문 | 필요할 때만, **왜, 무엇**을 불릿, `어떻게`는 코드가 말함 |
| PR 본문 | 요약, 변경, 영향/리스크, 테스트, (표, 불릿) |
| 공통 금지 | AI 서명, 흔적, 과잉 서술, 제목/본문 중복 |

프로젝트에 이미 정한 컨벤션(언어, 형식)이 있으면 그것을 우선합니다.

## 1. 커밋 제목

- 형식: `<type>[scope]: 요약`
- type: `feat`, `fix`, `docs`, `refactor`, `perf`, `test`, `chore`, `build`, `ci`, `revert`
- 요약: 명령형, 현재형("추가", "고침" > "추가하였음", "고쳤습니다"), 72자 이내, 끝 마침표 없음
- **제목을 `~한다`로 끝내지 않습니다.** 제목은 문장이 아니라 라벨입니다. 명사형으로 끊습니다
- 언어: 프로젝트 관례를 따릅니다(한글/영어). 한 저장소 안에서 섞지 않습니다.
- 무엇을 바꿨는지 한 줄로. 모호한 요약("여러 개선", "버그 수정") 금지. 무엇을 개선/수정했는지 적습니다.

## 2. 커밋 본문

- 제목으로 충분하면 본문을 쓰지 않습니다.
- 쓸 때는 **왜 이 변경이 필요한지, 무엇이 바뀌는지**를 불릿으로. `어떻게`는 diff가 말하므로 적지 않습니다.
- 한 커밋 = 한 관심사. 무관한 변경을 한 커밋에 섞지 않습니다.
- 파괴적 변경, 마이그레이션, 롤백 방법은 본문에 명시합니다.

## 3. PR 본문

| 섹션 | 내용 |
| --- | --- |
| 요약 | 이 PR이 무엇을, 왜 (1~2줄) |
| 변경 | 주요 변경 불릿 |
| 영향/리스크 | 호환성, 마이그레이션, 성능, 보안 영향 |
| 테스트, 검증 | 무엇을 어떻게 확인했는지(명령, 결과) |

- 산문 문단 대신 표, 불릿로 스캔 가능하게.
- 스크린샷, 재현 절차가 필요하면 넣되, 설명은 짧게.

## 4. 금지

- AI 서명, 흔적: `🤖 Generated with …`, `Co-Authored-By: …AI…` 등. (사용자 전역 규칙과도 일치)
- 과잉 서술: "이번 커밋에서는 ~를 진행하였습니다", "~하도록 하였습니다" 류 미사여구.
- 제목과 본문에 같은 문장 반복.
- 번역투, AI 문체([translationese.md](translationese.md) 대조표 적용).

## 5. Before / After

### 커밋 제목

| Before | After |
| --- | --- |
| `수정: 로그인 관련 여러 버그를 수정하였습니다.` | `fix(auth): 세션 만료 후 재로그인 실패 수정` |
| `update code` | `refactor(cal): occurrence 확장 로직 분리` |
| `feat: 목록에 GPU 수량을 채운다` ← 평서체 종결 | `feat: 목록에 모델별 GPU 수량 집계 추가` |
| `docs: 대체품임을 주석에 남긴다` ← 평서체 종결 | `docs: 폴링이 watch의 대체품이라는 사실을 기록` |

```bash
# 제출 전 한 줄 검사
git log --format='%s' main..HEAD | grep -E "다$" && echo "제목이 평서체로 끝난다"
```

### 커밋 본문

Before

> 이번 커밋에서는 사용자 인증 기능을 새롭게 추가하였으며, 이를 통해 다양한 방식으로 로그인을 손쉽게 수행할 수 있도록 개선하였습니다.

After

```text
feat(auth): 이메일+비밀번호 로그인 추가

- GoTrue 세션 발급, RLS is_member로 프로젝트 접근 제한
- ENABLE_EMAIL_AUTOCONFIRM로 SMTP 없이 가입 (변경 시 auth 컨테이너 recreate 필요)
```

제거한 것: `이번 커밋에서는`, `새롭게`, `이를 통해`, `다양한`, `손쉽게`, `수행할 수 있도록`, 존댓말.

### PR 본문

Before

> 본 PR은 캘린더 허브 기능을 구현한 것으로, 여러 도메인을 통합하여 사용자가 편리하게 일정을 관리할 수 있도록 하는 다양한 기능들을 포함하고 있습니다.

After

```markdown
## 요약
캘린더 허브 + 일정(events) 추가. 일정, 가계부, 반복, 할일을 한 화면에 레이어로 표시.

## 변경
- events 테이블 + RLS
- 월/아젠다 뷰, 레이어 토글, 듀오 겹침 바
- 일정 CRUD(Dialog/Drawer), 네이티브 date/time

## 영향
- 스키마 additive(기존 데이터 무영향)

## 테스트
- npm run build 통과, 로컬에서 일정 추가/편집/삭제 확인
```
