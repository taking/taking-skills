# taking-docs

한국어 기술 문서와 코드 주석을 자연스럽고 정확하게 작성하고 검토하는 Claude Code Skill입니다. README, 설계 문서, ADR, API 문서, 코드 주석, 커밋 메시지, PR 본문을 다룹니다.

## TL;DR

| 항목 | 기준 |
| --- | --- |
| 최우선 | 기술적 정확성, 의미 보존 |
| 문장 | 명확하고 자연스러운 한국어, 모호성 제거 |
| 문단 | 의미 단위로 묶고 불필요한 줄바꿈 제거 |
| 구조 | 문단, Dash 목록, 번호 목록, 표, Mermaid, SVG를 내용에 맞게 선택 |
| 코드 주석 | WHAT보다 WHY와 계약, 코드 개선 우선 |
| 언어 | 한국어 중심, 정확한 영어 기술 용어 유지 |
| 기본 톤 | 존댓말, 기존 프로젝트 관례 우선 |

ASD-STE100의 명확성, 용어 일관성, 모호성 제거 원칙을 참고합니다. 공식 표준의 전체 규칙을 한국어 문서에 기계적으로 적용하지 않습니다.

## 트리거

한국어 기술 문서와 코드 주석을 작성, 수정, 번역, 리뷰할 때 사용합니다. 영어 기술 문서를 한국어로 옮기거나 번역투와 AI 문체를 정리할 때도 사용합니다. 직접 호출은 `/taking-docs`입니다.

## 구성

`SKILL.md`는 핵심 원칙과 작업 경로를 안내합니다. 상세 규칙은 각 정본 파일에 있습니다.

| 경로 | 역할 |
| --- | --- |
| `SKILL.md` | Skill 진입점과 핵심 규칙 |
| `style-guide.md` | 기술 문서 작성 규칙의 정본 |
| `checklist.md` | 기술 문서 제출 전 점검 |
| `workflows.md` | 작성, 리뷰, 재구성 절차 |
| `reference/translationese.md` | 번역투와 AI 문체 대조표 |
| `reference/commit-pr.md` | 커밋 메시지와 PR 본문 규칙 |
| `templates/` | 문서 종류별 시작 템플릿 |
| `examples/` | 좋은 예, 나쁜 예, Before/After |
| `evals/` | Skill 회귀 평가 시나리오 |
| `scripts/lint-docs.sh` | Markdown 형식 및 문체 검사 |
| `code-comments/` | 코드 주석 규칙, 언어별 규칙, 템플릿, 예제 |

## 정보 표현 방식

- **문단:** 배경, 판단 근거, 원인과 결과
- **Dash 목록:** 독립된 항목, 책임, 기능, 조건
- **번호 목록:** 순서가 중요한 절차
- **표:** 비교, 속성, 설정값, 계약
- **Mermaid:** 처리 흐름, 상호작용, 상태, 컴포넌트 관계
- **SVG:** Mermaid로 표현하기 어려운 정교한 구조

표와 다이어그램을 무조건 우선하지 않습니다. 정보의 정확성과 논리적 완결성을 유지하면서 가장 명확한 형식을 선택합니다.

## 핵심

- 문장마다 줄바꿈하지 않고 의미 단위로 문단을 구성합니다.
- 문서의 가독성은 줄바꿈의 개수가 아니라 정보의 배치와 문단의 응집도로 결정됩니다.
- 짧게 쓰는 것보다 정확하고 명확하게 쓰는 것을 우선합니다.
- 기술적 근거와 제약은 유지하고, 불필요한 반복과 포장 표현을 줄입니다.
- 코드 주석은 코드, 이름, 구조를 먼저 개선한 뒤 필요한 WHY와 계약만 남깁니다.
